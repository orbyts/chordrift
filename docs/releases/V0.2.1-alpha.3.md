# Chordrift v0.2.1-alpha.3

This prerelease removes the whole-library network bottleneck discovered while
recording 28 direct playlist moves.

## What changed

- Active assignment revisions are replayed with set-based PostgreSQL statements
  instead of several sequential Neon queries per historical decision.
- All inferred moves to one destination are recorded in one atomic transaction
  and one CLI session rather than one session per track.
- The maintenance wizard reports when it is preparing an editable proposal and
  how many moves it is recording, so legitimate work is no longer a silent gap.
- Direct moves remain Neon-only intent updates. They do not repeat or undo the
  provider edits already made by the user.

## Performance proof

The reported alpha.2 run contained 615 active assignment revisions and 28 new
moves. Its proposal extension took about 83 seconds because the old replay path
performed roughly 1,800 network round trips.

An isolated representative PostgreSQL 18 rehearsal contained 610 active
revisions and 7,918 playlist memberships. Alpha.3 replayed the decisions and
extended the proposal in 1.12 seconds locally. A two-track atomic assignment
completed in 0.09 seconds. Coverage, active-revision counts, and all 599 manual
memberships were verified; the disposable benchmark database was then removed.

## Re-evaluate and future artwork

The inactive empty `Re-evaluate` playlist may be deleted directly in Spotify.
Chordrift retains its Neon history and will not recreate the surface. Its
approved background and rendered cover remain in `artwork/review/` for possible
reuse during the separately reviewed alpha.4 playlist expansion.

## Install

```console
$ cargo install chordrift --version 0.2.1-alpha.3 --locked --force
$ rehash
$ chordrift --version
$ chordrift capabilities --require maintenance.unified-workflow.v1
```

This alpha does not begin Hosted Rust Authority work. V021-01 through V021-06
and the intended v0.2.1 final daily-driver release remain unchanged.
