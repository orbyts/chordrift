# Chordrift v0.2.1-alpha.10

Alpha.10 freezes the first wrapper-neutral ordinary-maintenance task boundary.
It is an architectural checkpoint on the way to the hosted Rust authority, not
the hosted service itself.

The Rust core now owns:

- typed maintenance start, refresh, ambiguity-resolution, authorization, and
  query DTOs;
- immutable session revisions and provider-snapshot preconditions;
- exact review binding and stale-authorization rejection;
- allowed client actions and client-safe workflow errors; and
- cumulative rebase behavior in which the newest complete provider snapshot
  supersedes older record-only intent and invalidates older authorization.

The same scenarios pass through direct in-process calls and JSON serialization,
so a future web, iOS, Android, or CLI wrapper does not reproduce domain policy.
Provider-authored membership-equal ordering remains record-only and needs no
provider authorization.

This release advertises application contract `1.1` and capability
`maintenance.task-session.v1`. The existing `chordrift-maintain.sh` remains the
daily-driver adapter in this alpha. V021-01 will connect the task contract to
real database/provider execution and authenticated HTTP; alpha.10 does not open
a network listener or distribute credentials.

Install the locked registry artifact with:

```console
$ cargo install chordrift --version 0.2.1-alpha.10 --locked --force
$ chordrift capabilities --require maintenance.task-session.v1
```
