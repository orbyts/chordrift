# Chordrift v0.2.1-alpha.9

This prerelease repairs an interrupted ordinary-maintenance sequence in which
recording direct intake revealed a membership-equal playlist reorder only in
the next plan.

## Repair

- Treat every complete Spotify pull as the newest baseline for user-authority
  state and preserve already recorded gestures across interrupted runs.
- After any record-only proposal revision, rebuild the plan and absorb newly
  exposed provider-order intent until the plan reaches a bounded fixed point.
- Refuse order alignment unless provider and proposal memberships are exactly
  equal and duplicate-free.
- Invalidate stale plans and never call `sync apply` while accepting provider
  order.
- Add the daily-driver edge-case ledger so every real-use failure becomes a
  documented product rule and regression.

## Recover the interrupted run

The direct intake for `Tum Hi Ho Bandhu` was already recorded. Do not move or
re-add tracks. Install alpha.9 and rerun ordinary maintenance:

```console
$ cargo install chordrift --version 0.2.1-alpha.9 --locked --force
$ rehash
$ scripts/chordrift-maintain.sh --account personal
```

Chordrift should print `Accepting current Spotify order: Celluloid Mehfil`,
rebuild the plan, and finish in sync without a Spotify membership or order
write.
