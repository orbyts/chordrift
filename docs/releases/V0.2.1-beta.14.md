# Chordrift v0.2.1-beta.14

Beta.14 restores provider-native intake parity across the hosted daily driver.
Liked Songs remains the primary convenience intake, but configured playlists
such as `Inbox`, `From Friends`, `Liked from Radio`, and `From Prompts` now
reach the same Rust maintenance projection instead of disappearing from a Web
or remote CLI maintenance session.

Discovery provenance and canonical placement remain separate. The maintenance
view preserves the exact intake source and asks for a destination when no
accepted or unambiguous recommendation exists. A recommendation may be
preselected, but it is not consent. Chordrift still requires an exact reviewed
destination addition and verification before any temporary intake membership
may be consumed.

The Web UI contains no parallel classification logic. Both currently supported
clients render the same contract 1.6 DTO produced by the Rust authority. New
single-source and composite-source regressions cover named intake plus Liked
Songs without contacting Spotify or production Neon. The database schema
remains 52.
