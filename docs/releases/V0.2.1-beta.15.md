# Chordrift v0.2.1-beta.15

Beta.15 completes the named-intake lifecycle introduced in beta.14. Tracks
discovered through `Inbox`, `From Friends`, `Liked from Radio`, `From Prompts`,
or another configured intake retain their source provenance while Chordrift
places them. When that intake is configured to clear after assignment,
Chordrift removes the source membership only after the destination is visible
in a fresh Spotify observation and the user authorizes a separate exact review.

Hosted verification now tolerates bounded provider eventual consistency. It
repeats read-only observations over a short backoff window without replaying an
already accepted destination write or clearing the safety copy early. Multiple
tracks removed from the same intake playlist are batched against one evolving
Spotify snapshot, preventing the first successful removal from making the next
one stale.

The permanent credential-free fake-provider harness reproduces the reported
sequence with two Inbox tracks, separate destinations, a stale post-write
observation, and composite cleanup. It proves the final Inbox is empty while
both destination memberships remain. Web and remote CLI continue to render and
authorize the same Rust contract 1.6 DTO; database schema 52 is unchanged.
