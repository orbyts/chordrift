# Chordrift v0.2.1-beta.5

Beta.5 repairs CLI authorization in a browser that does not already hold a
Chordrift product session.

After the installed CLI prints its one-time authorization URL, Safari can now
follow that request through Google/Chordrift login and return to the same
consent page. The exact loopback URI, client state, and PKCE challenge survive
the round trip; the browser still never receives the PKCE verifier or a product
session intended for the CLI.

Post-login continuation is limited to Chordrift's internal CLI authorization
route. Absolute URLs, scheme-relative URLs, unrelated paths, fragments, and
header-injection inputs are rejected. Chrome's Safe Browsing classification of
the private-beta hostname is a separate reputation issue and is not bypassed.
