# Chordrift v0.2.1-alpha.16

This daily-driver checkpoint makes redundant Liked Songs intake explicit and
remembered without changing the hosted-authority sequence.

## What changed

- When a newly liked track is already present in a verified Chordrift-managed
  playlist, the ordinary wizard names that destination before proposing any
  saved-state change.
- The wizard asks whether the track should remain in Liked Songs too. The
  per-track answer is revisioned as an include/clear directive on a virtual
  Liked Songs intake surface already supported by migration 0046.
- Undecided and keep states cannot plan an Unlike. Clear permits one exact
  reviewed saved-state removal after verified placement; it never removes the
  managed destination.
- A later direct Unlike in Spotify is accepted as newer provider-side intent
  and supersedes an older keep decision after exact record-only convergence.
- Application contract 1.3 adds the provider-neutral `consume_intake`
  resolution, and the binary advertises
  `maintenance.saved-intake-disposition.v1`.

## Verification boundary

Fake-binary coverage proves the review uses track, artist, and destination
names and performs no mutation in review-only mode. Disposable PostgreSQL
coverage proves undecided safety, remembered keep, explicit clear planning,
superseding revisions, and direct-Unlike convergence. No personal Neon or
Spotify access is required for implementation or CI.

Local ordinary maintenance still requires only migration 0047. Migrations
0048 through 0050 remain the unapplied hosted identity, credential-vault, and
durable-operation foundation until deployment.
