# Chordrift v0.2.1-beta.8

Beta.8 replaces Chordrift's custom installed-CLI browser protocol with Auth0's
standard OAuth 2.0 Device Authorization Flow.

`chordrift service session login` now obtains a short device code from the
configured public Auth0 Native application, opens Auth0's verification page in
the operating-system default browser, and polls only at Auth0's prescribed
interval. After Auth0 authenticates and authorizes the user, Chordrift verifies
the issuer credential and creates the same separate, account-scoped, revocable
machine session stored by earlier betas.

The CLI no longer opens `/auth/cli/authorize` or `/auth/cli/approve`, runs a
localhost callback listener, or depends on a Chordrift browser cookie. Auth0
credentials and Chordrift session tokens are never printed or placed in browser
URLs. `--no-open` remains the browser-neutral and headless fallback.

Spotify authorization remains independent and server-owned through `chordrift
service provider spotify connect`.
