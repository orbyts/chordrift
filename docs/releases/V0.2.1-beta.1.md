# Chordrift v0.2.1-beta.1

This is the first private-beta dual-client daily driver. The web workbench and
installed remote CLI are presentation adapters over the same authenticated Rust
command/query/event contract and durable worker. The web client does not invoke
the CLI, and neither client receives Neon, Spotify refresh, Auth0, or vault-key
credentials.

Google login establishes a revocable Chordrift session. Spotify authorization
is independent and may be connected, reconnected, disconnected, or extended to
another provider account without discarding the existing Chordrift library.
Ordinary maintenance observes the provider first, records direct user edits as
cumulative intent, asks only for genuine ambiguity, and requires immutable
review before any server-authored provider effect.

The release includes the hardened cases discovered during daily use: direct
playlist intake, paired moves, user-authored order, Liked Songs disposition,
safe destination-before-source removal, stale browser sessions, duplicate
catalog editions, interrupted retries, and provider observation delay. The CI
fake-provider matrix covers single and composite gestures without production
credentials or network access.

Install and authorize the remote CLI with:

```console
$ cargo install chordrift --version 0.2.1-beta.1 --locked --force
$ chordrift service session login --url https://chordrift.suhail.ink
$ chordrift service compatibility --url https://chordrift.suhail.ink
```

The hosted API and worker run from the same tagged source commit as the
published CLI. Their exact source revision, image digest, local installed
version, and live health results are recorded in the private deployment proof.
Provider writes remain restricted to an exact user-reviewed maintenance effect;
this is not an unrestricted public launch.
