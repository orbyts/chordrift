# Chordrift v0.2.1-alpha.13

Alpha.13 repairs the ordinary provider-first convergence boundary found during
daily Spotify use. An assignment revision already satisfied by its destination
now preserves the accepted provider order instead of deleting and appending the
track by revision chronology. This stops the alternating Celluloid Mehfil /
Kaveri Resonance order loop.

After record-only maintenance reaches exact ordered equality, the Rust core now
records that complete provider observation as the next immutable managed
baseline. A later removal is therefore interpreted as a new exclusion and an
older approved proposal cannot silently add the track back. This acceptance
step neither contacts nor writes Spotify.

The active reversible exclusion archive is visible and separately clearable:

```console
$ chordrift tracks exclusions --account personal
$ chordrift tracks empty-exclusions --account personal --confirm personal
```

Emptying the archive retains historical evidence and an internal forget
tombstone, changes only Neon intent, and is refused while an excluded track is
still present in the current provider observation. The tombstone is hidden from
the active archive and prevents an older proposal from restoring the track. It
is not a Spotify deletion command.

The complete authority and interruption rules are normative in
[Provider-first convergence](../design/PROVIDER_FIRST_CONVERGENCE.md). The
temporary daily wrapper remains:

```console
$ scripts/chordrift-maintain.sh --account personal
```

Install and verify with:

```console
$ cargo install chordrift --version 0.2.1-alpha.13 --locked --force
$ chordrift capabilities --require maintenance.provider-baseline.v1
```

This daily-driver repair does not apply migration 0048, access Neon, or write
Spotify. V021-03 remains the next hosted-authority slice after alpha.13 is
released and verified.
