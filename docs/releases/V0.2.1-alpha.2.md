# Chordrift v0.2.1-alpha.2

This corrective prerelease makes the unified ordinary-maintenance wizard safe
for direct moves between managed Spotify playlists.

## What changed

- A track added to a new managed destination and removed from its old canonical
  destination is recorded as reclassification before apply. Chordrift does not
  delete the track from the destination the user selected.
- One confirmation covers only the exact plan phase shown in the summary. If a
  pull reveals different follow-up work, the wizard stops and asks the user to
  run it again; it never applies that work under the earlier confirmation.
- Ordinary summaries show track titles, artists, and playlist names. Spotify
  IDs, plan UUIDs, and readiness UUIDs remain available to lower-level
  diagnostic commands but are not part of the daily interaction.
- Fake-binary shell tests reproduce the recovered Dakshina Pulse → Uttara Glow
  failure shape and prove a later exclusion plan cannot be applied
  automatically.

## Recovery completed before release

The six tracks affected during alpha.1 testing were restored to Uttara Glow.
A fresh Spotify pull verified every track present there and `excluded: false` in
Chordrift. The separate empty `Re-evaluate` retirement remains deferred and was
not included in the restoration authorization.

## Install

```console
$ cargo install chordrift --version 0.2.1-alpha.2 --locked --force
$ rehash
$ chordrift --version
$ chordrift capabilities --require maintenance.unified-workflow.v1
```

Then use the same daily command:

```console
$ unset CHORDRIFT_BIN
$ scripts/chordrift-maintain.sh --account personal
```

This alpha does not begin the Hosted Rust Authority work. V021-01 through
V021-06 and the intended v0.2.1 final daily-driver release remain unchanged.
