# Chordrift v0.2.1-beta.12

Beta.12 adds the server-owned account-presentation capability required for a
top-right Web profile avatar. Existing Chordrift login and authorization remain
unchanged: Auth0/Google proves product identity, Chordrift issues its own
revocable account-scoped session, and Spotify remains a separate provider
connection.

After Auth0 UserInfo verification, Chordrift now records a bounded display name
and a sanitized HTTPS Google profile-image URL beside the external identity.
These fields are presentation metadata, not authorization claims. Email,
identity credentials, Neon access, and Spotify credentials remain server-only.
The authenticated `/auth/session` response keeps `signed_in`, `subject_id`, and
`account_id` and adds nullable `display_name` and `avatar_url` fields. No
maintenance, library, provider, or shared command/query DTO changes.

The browser security policy permits profile images only from Google's
`googleusercontent.com` image hosts. Other or malformed picture URLs are
discarded and the browser must show an accessible initials/default fallback.
An existing long-lived Chordrift session has no retained Auth0 credential, so a
user signs out and back in once to populate the new fields; later Web or CLI
product logins refresh them.

Additive migration 0052 adds the optional presentation columns and their last
verification timestamp to `product_external_identities`. Unit coverage bounds
names and rejects insecure, credential-bearing, fragmented, or non-allowlisted
avatar URLs. Disposable-PostgreSQL coverage verifies durable profile refresh and
subject-scoped retrieval.
