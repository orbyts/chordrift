# Chordrift v0.2.1-alpha.11

Alpha.11 completes V021-01: the wrapper-neutral maintenance contract is now
served by one asynchronous Rust authority both in process and over authenticated
HTTP.

The HTTP surface accepts only typed command/query envelopes. It has no route for
running CLI commands, shell scripts, SQL, or arbitrary provider requests. The
Rust service owns idempotency, maintenance revisions, allowed actions, exact
authorization, application/provider sequencing, lifecycle events, reconnect,
cancellation, and cumulative refresh.

The real HTTP conformance suite proves authentication and account isolation,
identical local/HTTP outcomes and provider traces, exact idempotent replay,
collision rejection, ordered event cursors, stale-review rejection,
provider-order acceptance without a provider write, structured rate limiting,
and secret-free malformed/incompatible errors.

This checkpoint advertises application contract `1.2` and capability
`service.authenticated-transport.v1`. It intentionally supplies no public
listener, production bearer token, hosted URL, Neon credential, or provider
credential. Product sessions begin in V021-02; the provider vault, durable jobs,
remote CLI, and deployment follow in V021-03 through V021-06.

Daily intake remains unchanged:

```console
$ scripts/chordrift-maintain.sh --account personal
```

Install and verify the locked registry artifact with:

```console
$ cargo install chordrift --version 0.2.1-alpha.11 --locked --force
$ chordrift capabilities --require service.authenticated-transport.v1
```
