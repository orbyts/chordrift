# Chordrift v0.2.1-beta.16

Beta.16 repairs the hosted PostgreSQL bridge for an already-placed track that
still remains in a provider-native intake playlist. The immutable planner was
correctly producing deferred `cleanup/remove_track` operations for the two
Inbox tracks, but beta.15 rejected that valid operation kind as a state
conflict before the Web or remote CLI could display the source-only review.

The adapter now accepts planner-owned named-intake cleanup, excludes it from
ordinary observed-delta annotation, and lets the intake projection emit exactly
one typed `ConsumeIntake` change. The user still authorizes the exact removal;
starting maintenance remains read-only and never treats the destination
placement as permission to remove the source silently.

The permanent adapter regression covers the exact provider state: Inbox and
Neon Affection both contain the track, canonical placement is already accepted,
and the source uses `after_verified_assignment`. The existing stateful fake
provider test continues to prove two-track cleanup, evolving Spotify snapshots,
and destination preservation. The provider/intent convergence matrix now
documents every supported resolution class. Contract 1.6 and schema 52 are
unchanged.
