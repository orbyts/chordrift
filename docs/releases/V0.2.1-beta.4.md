# Chordrift v0.2.1-beta.4

Beta.4 makes explicit CLI consent work in privacy-aware browsers that omit both
`Origin` and `Referer` on a same-site form POST.

The authenticated authorization page now issues a high-entropy one-time
consent token. Chordrift stores only its SHA-256 digest with the expiring,
subject-bound PKCE attempt and requires the exact token on approval. A forged,
cross-subject, expired, already-approved, or replayed request fails closed.

The stricter origin/header requirement remains in place for other browser
mutations. This narrowly scoped consent protocol does not expose provider or
database credentials and does not bypass Google Safe Browsing.
