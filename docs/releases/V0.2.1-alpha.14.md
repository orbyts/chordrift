# Chordrift v0.2.1-alpha.14

Alpha.14 completes V021-03: provider OAuth refresh credentials can remain
inside the hosted Rust authority instead of being distributed to shipped
clients.

## What changed

- Refresh credentials are encrypted with XChaCha20-Poly1305 before persistence.
- Authenticated metadata binds ciphertext to one Chordrift account, provider
  account, provider namespace, credential kind, algorithm, revision, and
  external key ID.
- Encryption keys remain in deployment configuration or a future KMS; neither
  plaintext credentials nor keys are stored in PostgreSQL.
- Active account members may obtain a short-lived internal provider lease.
  Only the active owner may provision, rotate, or revoke a credential.
- Rotation atomically supersedes the prior generation, revocation is immediate,
  and the database retains encrypted audit history while enforcing one active
  generation.
- Tampering, missing keys, tenant mismatch, and identity substitution fail
  closed through fixed secret-free errors.
- The capability manifest adds
  `service.provider-credential-vault.v1`. Application contract 1.2 and product-
  session schema 1 are unchanged.

## Database boundary

Additive migration 0049 contains only the encrypted provider-credential vault.
It was rehearsed on disposable PostgreSQL and was not applied to the personal
Neon database. Local ordinary maintenance continues to require only migration
0047, so `47/49` with two hosted migrations pending is expected.

There is no public raw-token route, hosted URL, selected identity vendor, KMS,
or deployment in this checkpoint. V021-04 adds durable background operations;
V021-05 adds remote CLI parity; V021-06 selects and verifies deployment.

## Install

```console
$ cargo install chordrift --version 0.2.1-alpha.14 --locked --force
```

The ordinary daily-driver command remains:

```console
$ scripts/chordrift-maintain.sh --account personal
```

The provider-first behavior of that workflow is unchanged. This release did
not contact Spotify, access the personal Neon project, or apply migration 0049.
