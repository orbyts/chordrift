# Chordrift v0.2.1-alpha.12

Alpha.12 completes V021-02 with persisted product identity, account ownership,
and revocable Chordrift bearer sessions.

External identity verification remains vendor-neutral. After a configured
verifier accepts an upstream credential, Chordrift checks an existing account
ownership binding, issues a 256-bit opaque token, and stores only its digest.
Expiry, logout, subject suspension, membership revocation, and account
suspension all invalidate access through the same authorization path.

Additive migration 0048 contains only hosted product identity/session tables.
The local maintenance CLI requires schema through 0047, so the installed alpha
can continue using the existing verified personal music database without
applying migration 0048. A hosted identity service must verify 0048 before it
accepts traffic.

This checkpoint keeps application contract `1.2` unchanged, adds independently
versioned product-session schema `1`, and advertises capability
`service.product-identity.v1`. It does not select an identity vendor, expose a
hosted URL, store Spotify credentials, or deploy a public service.

Daily intake remains:

```console
$ scripts/chordrift-maintain.sh --account personal
```

Install and verify with:

```console
$ cargo install chordrift --version 0.2.1-alpha.12 --locked --force
$ chordrift capabilities --require service.product-identity.v1
```
