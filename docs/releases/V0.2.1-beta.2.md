# Chordrift v0.2.1-beta.2

This private-beta repair hardens the browser-mediated remote CLI login found
during beta.1 deployment acceptance.

Some browsers or privacy/interstitial boundaries omit `Origin` from a native
same-origin form submission. Chordrift now accepts an exact parsed same-origin
`Referer` as the narrowly scoped fallback. An absent source, a different
scheme, a lookalike hostname, or any cross-origin source still fails closed.
The authenticated Chordrift subject, one-time expiring flow, PKCE verifier, and
exact loopback callback remain mandatory.

The installed CLI also flushes the complete authorization URL before opening a
browser and waiting for the callback. A user can therefore copy that URL into
another trusted browser if the operating-system default browser blocks the
private-beta hostname. Product sessions remain separate, revocable credentials
stored by the operating system; Spotify and database credentials are never
sent to the CLI.

The Chrome Safe Browsing warning observed on the private hostname is tracked as
an independent deployment/reputation incident. Users must not bypass it merely
to complete CLI authorization.
